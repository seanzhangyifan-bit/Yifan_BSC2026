# Examples: already-produced outputs

Three real spreadsheets, produced by real runs of `scripts/batch_stats/` against the private
micrograph collection (`data/raw/` in the parent repo — not bundled here, see the root README's
"What's not included"). These prove the batch export was actually exercised on real data, not
just unit-tested against synthetic images. They **cannot be regenerated from this export alone**
— that needs the private source images — but the numbers in them are real, already-produced
output, not a mockup.

| File | Produced by | Scope |
|---|---|---|
| `crack_stats_v1_full_dataset.xlsx` | `export_crack_stats.py` | The full 39-image dataset (every replicate that passed the scale-bar/size checks) |
| `crack_stats_v2_thesis_stats.xlsx` | `export_crack_stats.py`, re-scoped | 19 images, flaking-aware re-run, columns renamed to match the thesis write-up's own notation (`crack`, `flaking`, `wcrack`, `N`, `fgc`, `ledge`, `ledge,gc`, `dgc`) |
| `crack_stats_v3_batch_bcd.xlsx` | `export_crack_stats_v3.py` | The same 19-image scope, alternate single-pass methodology — see `../docs/batch_stats/crack_stats_v3_status.md` for the v1-vs-v3 comparison |

See `../docs/batch_stats/crack_stats_schema.md` for what every column means, exactly.

**Not bundled here, and why**: the master spatial-overview HTML report and the synthetic
validation gallery's report both reference their overlay/rose-diagram PNGs by relative path
rather than embedding them — copying the HTML alone would just produce a page full of broken
image links, not a working example. The validation gallery in particular needs no private data at
all (its synthetic test images are generated by code already in this export) — regenerate it
yourself in seconds:

```
python3 -m scripts.validation.validation_gallery
# then open outputs/validation/report.html
```
